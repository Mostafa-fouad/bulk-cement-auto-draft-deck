Supplier Quote Pricing → Extraction

Deck open presentation ↗ Length 6 slides · 6–8 min Controls → next · ← back · F fullscreen
How to use this

Each slide has four parts so you can present cold — no prep needed:

  • On screen — what the audience sees, so you stay in sync.
  • Say this — a natural script you can read almost word-for-word.
  • Key points — the must-land ideas if you go off-script.
  • Transition — one line to move to the next slide.
The 15-second version (hallway pitch)

Procurement receives supplier quotations as PDFs and photos — often scanned Arabic documents — and types every line into the supplier portfolio by hand. That takes about 130 hours a month. We extract the products and prices with AI, a person confirms each line, and then we write to the portfolio. Same judgment, almost none of the typing — down to about 9 hours a month, a 93% cut.

One thing to remember

We extract the document. They still confirm the line. If you land only one idea, land that one.

How It WorksUpload. Extract. Confirm. Write.

On screen

Four boxes, a sticky note "we extract — they still confirm," and a footer that AI proposes and procurement confirms.

Say this

Four steps. Upload the PDF or photo with the supplier and the city — a quote prices one city. Extract: AI returns line items with a confidence score. Confirm: match the SKU and unit, edit the price if needed, create the product only if it's new. Write: the existing portfolio API. Nothing is written until a person confirms the line. We extract. They still confirm.

Key points
  • Walk the four boxes once. That's the whole product.
  • Land the sticky note: AI proposes, procurement confirms.
  • Don't open Approaches A/B/C unless asked.

Q&A prep — likely questions

Are you letting AI write prices into production?

No. Extraction is a proposal. Nothing is written until a person confirms the line — SKU, unit, and price. They can edit before confirming.

What about scanned Arabic documents?

That's the main input. Extraction returns raw text plus a per-line confidence score. Low-confidence or messy lines are exactly why confirmation is one-by-one, not a bulk apply.

What if the product doesn't exist in the catalogue?

Create it first, using the same AI naming conventions we already use for products extracted from documents — bilingual EN/AR, live category and unit lists — then confirm the price. Creation stays behind the human gate; we don't auto-approve garbage from a bad scan.

Which approach are we taking — A, B, or C?

The recommended shape is Approach A for extraction (a quote type in document-extraction-service) plus a small catalogue naming endpoint at confirmation time — the hybrid in the design note. Prices stay out of the catalogue service. If someone wants the bake-off, point them at the design doc; don't derail the talk.

Do we need a new API to write prices?

No. Each confirmed line calls the existing PATCH on supplier-service that already find-or-creates the portfolio document for (supplier, city, country) and writes the per-unit price. N lines, N calls — that matches one-by-one confirmation.

How did you get to 93% / 130 hours / 9 hours?

That's the procurement team's estimate of time spent re-keying quote documents today versus time spent reviewing extracted lines. State it as their number. Don't invent a study behind it.

Does this auto-draft quotations / fill RFQs?

No — that's a different idea. This talk is only about getting quote prices into the portfolio. Filling the portfolio is what later lets auto-pricing and Mizan work. Don't mix the two.

How does this fit the bigger picture / Mizan?

This is the input side of a central pricing engine. Authoritative prices live in the portfolio. Extracting them from supplier quotes — with a human confirm — is the first concrete step so every module can read from one place instead of rebuilding pricing per feature.

Which teams were involved?

Glossary

Supplier quote
A PDF or photo from a supplier listing products, units, and prices — often scanned Arabic with mixed AR/EN.
Supplier portfolio
The store of supplier prices per product, unit, city, and country. The write target of this flow.
Extraction
An AI pass that turns a document into structured line items (raw text, qty, unit, unit price, confidence).
Confirmation
The human step: match SKU and unit, review/edit the price, then allow the write.
Catalogue / SKU
The product master. Quote lines must resolve to a catalogue SKU before they can be priced.
Canonical naming
The existing bilingual (nameEn / nameAr) rules used when creating products from documents.
Mizan
The direction for quotation auto-pricing off a central pricing engine. This flow feeds that engine; it is not Mizan itself.
Central pricing engine
Company direction: one place holds prices, every module reads from it — instead of pricing logic per feature.

Presenter tips

  • Pace: ~1 minute per slide. Don't skip any — there are only six.
  • The three anchors: (1) "we extract, they still confirm," (2) "93% — 130 hours down to 9," (3) "this fills the portfolio for a central pricing engine." Land those three and the talk succeeds.
  • Don't mix the other idea: this is not auto-drafting RFQs. If asked, say that's a later step once the portfolio is the source of truth.
  • If you blank: read the "Say this" line for the current slide. It's written to be spoken as-is.
